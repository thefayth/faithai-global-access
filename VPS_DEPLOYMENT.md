# FAITHAI VPS deployment

This is the primary low-cost production profile. It uses the existing VPS and PostgreSQL, serves the PWA through Nginx, and keeps the API on `127.0.0.1`. It does not activate ExoClick, hosted AI, payments, SMS/USSD, or emergency dispatch.

## Prepare a release

```sh
npm ci
npm test
npm run build
DATABASE_URL='postgresql://...' npm run db:migrate
```

Copy the reviewed release to `/opt/faithai/current`, copy `deploy/vps/faithai.env.example` to `/etc/faithai/faithai.env`, replace local placeholders there, and restrict that file to the service account. Do not place `DATABASE_URL` or provider secrets in any `VITE_*` variable.

Create `/var/backups/faithai` for the service account and install the backup scripts with mode `0750`. The included backup job writes a PostgreSQL custom archive plus a SHA-256 receipt; it deliberately does not auto-delete older archives.

Install the Nginx and systemd templates only after replacing `faithai.example` with the reviewed domain. The service binds to loopback; Nginx is the only public entry point.

## First launch

1. Keep every external provider flag `false`.
2. Apply the PostgreSQL migration and verify `/healthz` reports `ok: true`.
3. Enable `faithai-api.service` and verify the static PWA plus `/v1/integrations/status`.
4. Enable `faithai-backup.timer`, run one backup manually, and verify it with `verify-backup.sh`.
5. Keep the prior release directory available for rollback.

## ExoClick staging

Create one publisher zone configured for SFW native/text-capable inventory. ExoClick controls the final creative returned by that zone, so “text-first” is a publisher-zone policy and review requirement, not something FAITHAI can truthfully force from JavaScript. Use the exact asynchronous tag values generated by the ExoClick dashboard:

```text
VITE_AD_PROVIDERS=exoclick
VITE_EXOCLICK_SCRIPT_URL=https://a.magsrv.com/ad-provider.js
VITE_EXOCLICK_ZONE_ID=<publisher zone id>
VITE_EXOCLICK_ZONE_CLASS=<generated ins class>
```

These values are public build configuration, not account credentials. Build and test the release while server-side `FAITHAI_EXOCLICK_ENABLED=false`; enable the server flag only after the zone, inventory categories, disclosure, mobile rendering, and payout terms are reviewed. The adapter always adds SFW blocking attributes and requires adult mode plus separate contextual-ad permission.

## Rollback

Set `FAITHAI_EXOCLICK_ENABLED=false` to stop new ad requests, rebuild without ExoClick client variables if the tag itself is compromised, and restart the API. For an application rollback, repoint `/opt/faithai/current` to the previous reviewed release and restart `faithai-api.service`. Database changes in the baseline migration are additive and are not automatically reversed.
